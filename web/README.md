# SEGPILOT live site

FastAPI backend (`backend/`) serving a static dashboard + live compression demo
(`static/`). No build step, no framework — plain HTML/CSS/JS, served directly.

## What it does

- **`GET /api/results`** — serves `web/results.json`, generated by
  `python -m segpilot.replay.report --json`. The dashboard reads this; it is
  never hand-typed into the frontend, so the site always reflects the latest
  committed measurement.
- **`POST /api/compress`** / **`GET /api/compress/{job_id}`** — the live demo.
  Submits a real Paritok hosted-GPU compression (async submit+poll, since we've
  measured the hosted GPU cold-starting for minutes at a time). Runs two
  compressions per submission: baseline (no kind/intent) vs SEGPILOT
  (kind+intent routed), so a visitor sees the actual lever from
  `docs/findings.md` #4 on their own text.

## Run locally

```bash
export PARITOK_API_KEY=pk_live_...
python -m segpilot.replay.report --out examples/reports/ --json   # writes web/results.json
uvicorn web.backend.main:app --reload
# open http://127.0.0.1:8000
```

## Regenerating the dashboard data

Any time the underlying measurement changes (more sessions recorded, a new
replay), regenerate and commit `web/results.json`:

```bash
python -m segpilot.replay.report --out examples/reports/ --json
git add web/results.json
```

Render does not run the replay harness at build/deploy time — `results.json`
must be committed so the deployed site has something to serve.

## Deploying to Render (the steps only you can do)

1. Push this repo to GitHub (already done).
2. On [render.com](https://render.com), **New → Blueprint**, point it at this
   repo. It picks up [`render.yaml`](../render.yaml) at the repo root
   automatically.
3. In the Render dashboard, set the **`PARITOK_API_KEY`** environment variable
   (marked `sync: false` in render.yaml, so Render prompts for it — it is never
   committed to the repo).
4. Deploy. First build takes a few minutes; subsequent pushes to `main`
   auto-deploy.
5. Known free-tier behaviour: the service sleeps after ~15 min idle and takes
   ~30–50s to wake on the next request. The frontend's status messages already
   account for slow responses.

## Rate limiting

`/api/compress` is the only endpoint that spends the project's Paritok quota.
Defaults (overridable via env vars in `render.yaml`): 5 requests/min per IP,
150/day globally. See `web/backend/ratelimit.py`.
